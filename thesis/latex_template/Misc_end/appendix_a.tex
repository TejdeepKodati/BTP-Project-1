\section{Microcontroller Architecture and Power Rail Regulation}
The physical telemetry sensing unit utilizes the Espressif ESP32-WROOM-32 microcontroller (DEVKIT V1 30-pin board). Because high-speed MicroSD SPI write transactions induce instantaneous transient current draws exceeding 100\,mA, powering the SD card directly from the ESP32 internal 3.3\,V LDO leads to supply voltage droop and flash filesystem corruption. To guarantee non-volatile logging integrity, an external AMS1117-3.3V low-dropout regulator is placed on the 5\,V primary rail to deliver a dedicated, decoupled 3.3\,V power domain.

\section{Ultrasonic Transducer Level Shifting}
The JSN-SR04T waterproof ultrasonic modules operate from a 5.0\,V supply rail to maintain maximum acoustic output power. While their trigger inputs tolerate 3.3\,V logic pulses directly from the ESP32, their echo output pins assert 5.0\,V TTL pulses that would destroy the ESP32 input pins (which are non-5V-tolerant). 

To ensure long-term reliability, a passive voltage divider is inserted between each sensor echo pin and the corresponding ESP32 GPIO input:
\begin{equation}
V_{\text{out}} = V_{\text{echo}} \left(\frac{R_2}{R_1 + R_2}\right) = 5.0\,\text{V} \left(\frac{2.0\,\text{k}\Omega}{1.0\,\text{k}\Omega + 2.0\,\text{k}\Omega}\right) = 3.33\,\text{V}
\end{equation}
This drops the logic high level to exactly 3.3\,V, safely within the ESP32 operating limits without introducing switching delay.

\section{Mechanical Design and Dimensional Tolerances}
The physical enclosure architecture is adapted from the OpenBikeSensor (OBS) mechanical design repository, comprising two primary sub-assemblies:
\begin{enumerate}
    \item \textbf{Main Sensor Enclosure (Seatpost Unit):} Measures $128\,\text{mm} \times 64\,\text{mm} \times 48\,\text{mm}$. It houses the 2-layer PCB, ESP32, NEO-6M GPS antenna, 18650 cell, and dual lateral acoustic horns aligned at $90^\circ$ relative to the forward direction of travel. Transducer rubber sealing rings provide an IP65 splash-proof seal.
    \item \textbf{Handlebar Display and Remote Unit:} Measures $54\,\text{mm} \times 42\,\text{mm} \times 28\,\text{mm}$. It clamps to 31.8\,mm or 25.4\,mm bicycle handlebars, housing the 0.96'' OLED display and the 12mm momentary event switch.
\end{enumerate}

\section{Backend Microservice REST API Reference}
The Go backend exposes RESTful HTTP endpoints for simulation orchestration and spatial querying:
\begin{itemize}
    \item \textbf{\texttt{POST /api/simulation/run}}\\
    Asynchronously initiates a SUMO microscopic simulation with specified corridor length, vehicle fleet count, random seed, and duration. Returns an active \texttt{task\_id}.
    \item \textbf{\texttt{GET /api/simulation/status?id=\{task\_id\}}}\\
    Queries execution progress percentage, completed TraCI steps, and active memory allocation from Redis cache.
    \item \textbf{\texttt{GET /api/bicycles}}\\
    Enumerates all available bicycle entities within the database, returning summary encounter counts and total trajectory distances.
    \item \textbf{\texttt{GET /api/bicycles/\{id\}/trajectory}}\\
    Returns GeoJSON Linestring geometry and timestamped kinematic arrays for the specified bicycle.
    \item \textbf{\texttt{GET /api/bicycles/\{id\}/conflicts}}\\
    Returns filtered close-passing events and XGBoost severity tiers associated with the selected bicycle.
    \item \textbf{\texttt{GET /api/telemetry/export.csv?bicycle\_id=\{id\}}}\\
    Streams the complete trajectory and sensor log as a formatted CSV download.
\end{itemize}
